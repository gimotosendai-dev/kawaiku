# 03 データ設計

ダミーデータ（`data/*.json`）とSupabaseのテーブル（`docs/schema.sql`）は**同じ項目名**にする。JSONからSupabaseに切り替えても画面側のコードを変えなくて済むように。

### event_templates（テンプレート）
events から date を除いた項目＋ `name`（テンプレート名）、`repeat_rule`（例：毎週火曜）。

### notices（お知らせ）
id, facility_id, title, body, published_on, expires_on

### closures（臨時休所）
id, facility_id, date, reason

### newsletters（おたより）
id, facility_id, month（`2026-11`）, file_url（Supabase Storage）

### facility_staff（施設職員）
user_id（Supabase Auth）, facility_id, role（`staff` / `admin`）
→ 職員は自分の施設のデータだけ編集できる（RLSで制御）。

## フェーズ1.5で追加
- **articles**（取材記事）：id, facility_id（null なら市全体の記事）, title, lead（リード文）, body（本文・Markdown）, cover_image_url, first_visit_note（初めての方へ）, status（`draft` / `reviewing`（施設確認中） / `published`）, published_on
- events に **organizer**（`facility` / `city`）を追加：市の子育て講座を「市のイベント」として載せるため

## フェーズ2で追加
- **guardians**（保護者）：user_id, display_name, phone, email
- **children**（子ども）：id, guardian_id, nickname（呼び名）, birth_month（`2025-08` のような年月のみ。月齢は表示時に計算）
  - ※生年月日は持たない。年月だけなら月齢を自動で更新できる
- **reservations**（予約）：id, event_id, guardian_id, child_ids, status（`reserved` / `cancelled` / `attended`）, source（`app` / `phone`：電話予約の手入力）, answers（アンケート回答）, created_at
- **waitlist**（キャンセル待ち）：フェーズ3

## フェーズ3で追加
- **stamps**：reservation_id, given_at
- **surveys / survey_answers**：参加後アンケート（施設だけが読む）

## 権限（RLS）の考え方
| データ | 誰でも | 保護者 | 施設職員 | 運営 |
|---|---|---|---|---|
| facilities, events(published), notices, closures, newsletters | 読める | 読める | 自施設を編集 | 全部 |
| events(draft) | × | × | 自施設のみ | 全部 |
| guardians, children | × | 本人のみ | × | × |
| reservations | × | 本人のみ | 自施設のイベント分のみ（子どもは呼び名・月齢だけ） | 件数のみ |
